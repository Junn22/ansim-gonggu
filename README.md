## 2026-09-15 점검 및 변경

관리자 저장 결과를 UPDATE 응답으로 즉시 반영한다. Realtime에 의존하지 않으며 중복 클릭을 방지하고 저장 실패 시 기존 상태를 유지한다. 지연된 조회 응답이 저장 결과를 덮어쓰지 않도록 처리한다.

공개 목록은 영상 대신 표지 이미지를 표시한다. referrerpolicy=no-referrer를 적용했지만 만료 또는 접근 불가 이미지를 복구하는 조치는 아니다. 검색어를 갱신 후에도 유지하며, 승인 취소 이벤트가 공개 RLS로 전달되지 않는 경우를 위해 30초 간격 및 탭 복귀 시 재조회한다. 수집된 게시물만으로 현재 공구 진행 여부를 보장할 수 없어 제목을 '육아 공구 모아보기'로 수정했다. 최신 수집이 오래됐으면 지연 안내를 표시한다.

## 미해결 사항과 확인된 근거

- 인수인계 문서의 'Realtime 꺼짐'과 달리 점검 당시 posts는 supabase_realtime publication에 이미 포함돼 있었다. 추가 활성화 SQL은 실행하지 않았다.
- 점검 당시 총 21건(승인 18, 대기 3), 마지막 scraped_at은 2026-09-04 06:08 UTC였다. 그 이후 새 저장 결과가 없다는 의미이며, Apify 실행 자체가 없었다고 단정할 수는 없다.
- 기존 공개 화면에서 이미지 로딩 실패를 재현했다. CDN 직접 탐색은 검증 브라우저의 ERR_BLOCKED_BY_CLIENT로 차단되어 CDN의 HTTP 응답을 확인하지 못했다. hotlink, URL 만료, 환경 차단을 구별해야 한다. 새 탭에서 로드되더라도 임베딩 시 Referer 차이로 hotlink가 발생할 수 있다.
- Apify는 로그인 화면까지 확인했다. Billing 잔여 사용량, 스케줄 입력 및 실행/웹훅 로그는 로그인 후 확인해야 한다. 유료 스크래핑은 실행하지 않았다.
- onlyPostsNewerThan='1 days' 설정은 이전 게시물을 매일 갱신한다는 보장이 없다. 최신 이미지 확보 후 필요 시 수집 시점에 서버에서 썸네일을 저장하는 파이프라인을 검토한다. 캐싱만으로 이미 접근 불가능한 이미지를 복원할 수 없다.
- 현재 RLS는 모든 authenticated 사용자에게 전체 조회/수정을 허용한다. 실제 공개 회원가입 설정과 관리자 한정 권한을 후속 점검해야 한다.

## 검증

관리자 성공 응답의 즉시 렌더링(Realtime 없음), 중복 클릭 억제, 실패 시 상태 보존을 모의 응답 테스트로 확인했다. 두 페이지 JavaScript 구문 검사를 통과했다. 실제 관리자 계정으로 클릭하는 종단 검증은 아직 수행하지 않았다. 백엔드, 분류 규칙 및 기존 검수 데이터는 변경하지 않았다.

계정 비밀번호·Apify 토큰·Supabase service_role 키를 이 공개 저장소에 추가하지 않는다.
